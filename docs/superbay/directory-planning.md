# 目录规划指南（给用户和 AI）

SuperBay 是 Windows 本地工具启动器，以用户选择的工作区为入口，按文件系统展示分类、工具和文件。目录不限定安全行业；先根据用户的工作内容设计，再使用软件识别规则检查结构。

## 为用户规划

1. 了解用途、现有目录、工具数量、常用工作流程、是否需要保留原位置，以及希望的分类深度。信息不足时先给可调整的初稿，涉及实际移动、覆盖或删除时先确认具体范围。
2. 按用户容易寻找的任务或领域分组，分类少而清晰；工具各自保留完整目录。不要照搬安全工具分类，也不要凭空假定用户安装了示例工具。
3. 给出工作区根目录、树形结构、分类用途和扫描深度建议；区分示例占位与已有文件。需要实际创建时先核对路径和现有内容，只创建约定的目录；移动已有工具前说明路径、启动命令和配置可能需要检查。
4. 验证实际结构可被扫描：工具项目不应被拆散，分类目录不应因直接放置脚本或项目标记而被识别成工具。空分类不会显示，创建后需要放入内容才能验证展示。

## 扫描规则

- 默认深度为 2，可在设置中调整为 1–16；根目录不计入深度。达到上限的普通目录作为条目，想继续展开需增加深度。
- 目录直接包含 `.exe`、`.bat`、`.cmd`、`.lnk`、`.ps1`、`.py`、`.jar`、`.js`、`.mjs`、`.cjs`，或 `pyproject.toml`、`package.json`、`Cargo.toml`、`go.mod`、`requirements.txt`、`.git` 时，识别为完整工具，不再展开。把脚本放在对应工具目录内，不要直接放在打算作为分类的目录内。
- 根目录直属的工具项目和普通文件也可作为条目。普通目录可以成为分类或目录条目；显示效果受深度和内容影响。
- 点开头的项目、`SuperGUI`、`SuperBay`、`node_modules`、`__pycache__`、`venv`、`vendor` 被跳过；README、笔记及部分常见元文件不会作为普通文件条目显示。指向工作区外的目录链接不会被扫描。
- 分类可使用 `A-01-名称` 或 `A-名称` 前缀辅助排序，界面会隐藏前缀；命名并非强制。不要依赖纯数字前缀被隐藏。

## 示例：设计工作区

```text
D:\DesignTools\                 # 工作区根目录
├── A-01-图像处理\             # 分类
│   ├── ImageTool\             # 示例工具，保留原有文件
│   │   └── ImageTool.exe
│   └── 批处理脚本\
│       └── convert.py
├── B-02-视频处理\
│   └── VideoTool\
│       └── VideoTool.exe
└── C-03-素材\
    └── 配色参考\
        └── palette.txt
```

示例名称不是软件依赖；按实际文件调整。若希望深入浏览素材下的多级文件夹，可提高扫描深度；否则到达上限的文件夹作为条目。工作区可以是已有目录，无需复制整个工具库。
